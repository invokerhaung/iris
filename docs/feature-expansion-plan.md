```
┌─────────────────────────────────────────────────────────────────┐
│                      扩展策略：双模式并行                        │
│                                                                 │
│   IRIS = 本地播放器 + 在线内容聚合器                              │
│                                                                 │
│   ┌───────────────┐         ┌───────────────┐                   │

│   │  FTP          │         │  分类浏览      │                   │
│   │               │         │  IPTV 直播    │                   │
│   └───────┬───────┘         └───────┬───────┘                   │
│           │                         │                           │
│           └─────────┬───────────────┘                           │

│           ┌───────────────────┐                                 │
│           │   统一播放器层     │                                 │
```

**类比**：就像手机上的"文件管理器"和"视频 App"合二为一——既能浏览本地文件，又能看在线视频，共用同一个播放器。

## 四、阶段 0 — 基础重构（1-2 周）

> **目标**：为多页面架构打地基，不改变现有功能。

### 0.1 引入路由系统

**现状**：无路由，直接渲染 PlayerView。
**目标**：引入声明式路由，支持多页面切换。

```
┌─────────────────────────────────────────────────┐
│              新路由结构                           │
│                                                 │
│  /  (初始路由)                                   │
│  ├── /home        ← 新增：首页（内容浏览）        │
│  ├── /player      ← 改造：播放器（从首页跳转）    │
│  └── /settings    ← 可选：独立设置页              │
│                                                 │
│  保留现有 Popup 机制用于侧边面板                   │
└─────────────────────────────────────────────────┘
```

**新增/修改文件：**
- `lib/router.dart` — 路由定义（使用 `go_router` 或保持原生 Navigator）
- `lib/main.dart` — 修改入口，根据是否有初始文件决定跳首页还是播放器

**决策点：** 是否引入 `go_router`？
- 方案 A：引入 `go_router`（声明式路由，支持深链接，CatFun 用 GetX 路由）
- 方案 B：保持原生 `Navigator` + 手动管理（与现有 Popup 机制一致）
- **建议**：方案 B，保持一致性，用 `Navigator.pushReplacement` 实现页面切换

## 十二、风险与注意事项

```
┌─────────────────────────────────────────────────────────────┐
│                        风险矩阵                             │
├──────────────────┬──────────┬───────────────────────────────┤
│ 风险             │ 等级     │ 应对策略                      │
├──────────────────┼──────────┼───────────────────────────────┤
│ 破坏现有播放器   │ 🔴 高    │ 阶段 0 严格分离路由，播放器   │
│ 功能             │          │ 代码不改动，仅扩展数据输入    │
├──────────────────┼──────────┼───────────────────────────────┤
│ 视频源 API 变更  │ 🟡 中    │ 抽象接口隔离，适配器可替换    │
├──────────────────┼──────────┼───────────────────────────────┤
│ 网络请求性能     │ 🟡 中    │ 并发控制 + 超时 + 缓存       │
├──────────────────┼──────────┼───────────────────────────────┤
│ 多平台兼容       │ 🟡 中    │ DLNA 仅桌面端，逐步适配      │
├──────────────────┼──────────┼───────────────────────────────┤
│ 状态管理膨胀     │ 🟢 低    │ 遵循现有 Zustand 模式，Store │
│                  │          │ 职责单一                      │
└──────────────────┴──────────┴───────────────────────────────┘
```

**核心原则**：
1. **不动播放器** — 现有 PlayerView、MediaPlayer 接口、两个引擎实现保持不变
2. **渐进式扩展** — 每个阶段独立可交付，不依赖后续阶段
3. **保持架构一致** — 新代码遵循 Zustand + Hook + Freezed 模式
4. **向后兼容** — 命令行传文件仍直接进入播放器
